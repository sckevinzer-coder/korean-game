# 난이도 확장 (단어 은행 + 새 문제 형식 + TTS) 설계

## 개요

MVP(TOPIK 1~2급, 10단어, 4지선다 2종)가 너무 쉽다는 피드백에 따라
난이도를 확장한다. UI 언어 일본어, 오프라인 우선은 유지한다.

## 목표 / 성공 기준

- TOPIK 1~6급, 급당 500개 이상 단어 학습 가능
- 문제 형식 5종 (기존 2종 + 듣기/쓰기/문장 빈칸)
- 듣기 문제에서 TTS 음성 재생 (모바일 + 웹)

## 페이즈

### Phase 1 — 단어 은행 확충

- `assets/words/topik{1..6}.json`, 급당 500개 이상
- 스키마 기존 유지: id, korean, reading, meaning_ja, example_ko, example_ja, topik_level
- AI 배치 생성 (50~100개씩) + 스크립트로 스키마/중복 검증
- 오역은 사용 중 발견 시 수정 (신고 기능은 범위 밖)
- 레벨 선택 화면: 1~6급 목록, 급별 단어 수 표시

### Phase 2 — 새 문제 형식

- 듣기: TTS 재생 후 4지선다 (뜻/단어 맞히기)
- 쓰기: 음성 또는 뜻을 보고 직접 입력, 정확도 판정 (조사 무시 옵션)
- 문장 빈칸: 예문에서 목표 단어 가리고 맞히기 (4지선다)
- 세션당 형식 믹스, 급별 가중치 (상급일수록 쓰기/빈칸 비중↑)
- 퀴즈 1~3개 소규모 풀 크래시 가드 유지 (≥4 게이트)

### Phase 3 — TTS 음성

- `TtsService` 인터페이스로 추상화
- 모바일 구현: `flutter_tts` (ko-KR)
- 웹 구현: Web Speech API (SpeechSynthesis, lang ko-KR)
- 음성 없을 때 폴백: 듣기/쓰기 문제는 텍스트 표시로 대체

## 범위 밖

- 사용자 단어장 편집/추가
- 서버 동기화 / 계정
- 오역 신고 기능

## 데이터 모델 변경

- `Word` 변경 없음 (스키마 동일)
- `QuizQuestion`에 `kind` 3종 추가: listening, writing, blank
- `QuizSession`에 형식 믹스용 가중치 설정 추가

## 검증

- 단어 JSON 스키마/중복/급 일치 테스트 (급당)
- 형식별 생성기 단위 테스트 + 화면 위젯 테스트
- 기존 44개 테스트 전부 유지
- TTS는 인터페이스 모킹 테스트 (실음성 검증은 실기기)
